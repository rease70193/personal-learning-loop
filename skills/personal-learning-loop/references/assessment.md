# 评估与到期复习

这是评分、掌握状态和复习调度的唯一规则来源。以下是透明可调的默认启发式，不宣称是经个体数据校准的最优算法。

## 先定义能观察到的标准

每个能力卡记录：具体能力、验收标准、必要前置。标准包含核心正确性和必要的独立性；能解决新场景的任务可用于迁移检验。

每次尝试记录：日期与会话、题目或任务、用户回答/作品位置、是否使用提示、结果、具体理由、来源依据。不会判断时记“不确定”，核查后再定；不拿流畅文风或自信语气当正确证据。

结果为“通过／部分通过／未通过／未测／不确定”。缺少用户回答是未测，不是零分。提示后通过仍保留“提示=是”。

## 掌握状态

| 状态 | 进入依据 |
|---|---|
| 未验证 | 只有自评、看过材料、导入记录或尚未测验 |
| 学习中 | 正在尝试，需要提示，或尚未满足验收标准 |
| 独立通过 | 无提示完成有效任务，满足验收标准 |
| 保持通过 | 最近一次失败或依赖提示之后，在至少两个不同日期连续独立通过，且这段连续通过中包含一次新变式或适当迁移 |
| 待巩固 | 已有通过记录，但新的有效测验暴露相关缺口 |

“保持通过”不是永久标签。用概念卡保存当前状态，以会话证据保留进步与回退过程。原先从未通过的失败留在“学习中”。

## 复习规则

默认成功间隔序列为 **1、3、7、15、30 天**，从本次有效复习日期加对应间隔，非从第一次学习日累计。能力卡保存 `review_stage`（0–4）、`next_review`、`last_assessed`、`success_streak`、`last_success`；后两项只描述最近一次失败/依赖提示之后的连续通过。

1. 新内容完成一次教学或练习后：级别 0，下次为次日；没有任何尝试且没有进入教学的能力可以不排日期。
2. 首次无提示通过，或失败后重获首次独立通过：级别 0、success_streak=1、last_success=本次日期，下次为次日；这一次只支持“独立通过”。
3. 连续序列中后续在不同日期无提示通过：success_streak 加一，级别加一（上限 4），更新 last_success；按新级别排下一次。能否升为“保持通过”另看上表，不由级别单独决定。
4. 部分通过、未通过、依赖提示：级别和 success_streak 归零，last_success 清空、transfer_passed=false，下次为次日；必要时先补一个前置。曾通过的能力改“待巩固”。历史通过证据保留，不因清空当前序列而删除。
5. 同日反馈后的重答不升级、不延长日期；首次独立通过也要使用未被泄露答案的新任务。明确的失败可缩短间隔，即使在同日。
6. 未测、不确定、用户无时间：不修改掌握或成功次数，保留原到期日；可以在本次计划里延期处理，不能伪记为复习完成。
7. 用户要求改变节奏时记录自定义间隔及原因，再据此排期。暂停主题时保留日期，恢复后先抽测，不自动补齐全部历史复习。

记录 last_assessed 时，使用最后一次有可判定实际作答的日期；“未测/不确定”不更新。正向间隔增长须有当前连续通过序列，不仅看日期变化。能力已安排复习时，额外的教学演示或普通提示练习不触发归零；只有旨在测量该能力、原本需要独立作答的有效尝试才用于以上状态转换。

## 如何选题

从当前主题内 `下次复习日 <= 今天` 的能力中选择，不按“未掌握”过滤。默认先选与当前任务相关的前置、近期反复出错项，再看逾期程度；每次按预算挑少量，其余留队列。

过期不等于遗忘。答对过的知识也要复习；题目用新表述或新场景，避免只记住原题答案。应复习概念或能力，而非强制每道错题分别排期。

## 错因与争议

可用概念不清、混淆、漏条件、输出不熟、迁移困难、题目歧义、环境问题等标签；允许多个或“待确认”。建议引用回答中的具体步骤再判断，不把所有错误强塞五类。

确认评分错误后，给原尝试追加更正说明；按有效证据重新计算当前状态和日期。不得删除历史或继续用错误判分推动退回。
